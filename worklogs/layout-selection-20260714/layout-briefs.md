# 尊嚴農業全站版型 A／B／C brief

日期：2026-07-14  
狀態：候選版型，不是現行規格  
固定基礎：清朗田野 3.3.0；所有方案共用既定色彩、雙字體、字級、14／4／2px 幾何、角色式陰影、深綠頁尾與 Aa 閱讀控制。

## 設計依據與排除項

本輪以 design-master Mode A 查詢「編輯內容站、長文、知識庫、Podcast、研究機構」後，只採用與既定規格相容的準則：

- 長文維持 65–75 個中文字元內的合理行長；本案沿用 780px 閱讀寬度。
- 三層以上頁面保留麵包屑；目前位置不能只靠顏色，須有文字或線條提示。
- 篩選、影音與所有主要操作必須可用鍵盤完成，視覺順序與 tab 順序一致。
- 空結果必須提供清除條件，不出現空白畫面。
- 圖片需有真實替代文字；圖示按鈕需有可存取名稱。
- 固定頁首不得遮住第一屏；桌機、平板與手機分別驗證。

查詢也提出「Vibrant block、藍橘色盤、Roboto、社群加入 CTA、scroll-snap、200–300ms 大動態」。這些與清朗田野、既定 Noto 字體、160ms 節制動態及網站任務不符，全部排除。研究機構查詢的作品集 hover 與訂閱轉換套路同樣不採用，只保留中性紙面、內容優先與快速索引原則。

## 共同拍板規則

- A／B／C 比較的是第一屏任務、資訊順序、網格與導覽關係，不比較色票。
- 不用裝飾性置中 Hero；每頁第一屏直接回答「這頁讓人先做什麼」。
- 不新增內容。截圖所見標題、摘要、日期、圖片與數字全部來自 LocalWP 擷取當下。
- 同一家族只選一個共用骨架；個別頁可以因內容量自動降級，但不另造私人模板。
- 明日若 Bobo 回覆混合方案，必須說清楚「外框／第一屏／內容流／手機」分別取自哪一案，不能只寫「A＋B」。

## 01 首頁

第一屏任務：讓第一次來的人在 10 秒內知道計畫在做什麼、目前有沒有重要警示，以及下一步可以從內容、田野或研究哪裡進入。首頁不是所有內容的縮圖總表。

### A｜任務先行（設計建議）

- 第一屏：左側計畫核心句與一個主要入口；右側保留即時高溫／豪雨警示及三個常用起點。
- 內容順序：任務起點 → 最新內容 → 田野誌 → 深綠影音帶 → 研究與行動。
- 桌機採 7:5 非對稱網格；手機先警示、再核心句與入口。
- 優點：農民與一般訪客最快找到下一步；首頁角色清楚。
- 代價：單一新聞或照片的品牌衝擊較弱。

### B｜編輯頭版

- 第一屏：一則真實主題內容作大幅頭條，旁欄放計畫簡介、警示與兩則次要入口。
- 內容順序：頭條 → 最新消息流 → 三大內容門 → 深綠影音帶 → 研究證據。
- 桌機採 8:4 頭版；手機頭條圖、標題、警示依序直排。
- 優點：像有編輯判斷的內容媒體，更新感強。
- 代價：需要穩定維護「哪一則是頭條」，否則首頁容易失焦。

### C｜田野展卷

- 第一屏：一張真實田野照片與靠左的計畫核心句，下一屏才出現三條閱讀路徑。
- 內容順序：場域印象 → 田野故事 → 知識資源 → 深綠影音帶 → 研究與團隊。
- 桌機以大照片和長留白形成章節；手機改成照片在上、文字在下，沒有文字壓圖。
- 優點：最有人與地方的感受，適合建立品牌記憶。
- 代價：工具與最新消息要多捲一屏才看到。

## 02 最新消息列表

第一屏任務：快速理解最近發生什麼，並能依類型或日期找到舊消息。

### A｜頭條＋時間流（設計建議）

- 第一屏：最新一則作 7:5 圖文頭條，右側列下一批消息；篩選工具在頭條下方。
- 後續以日期分段的單欄消息流呈現，不把每則都做成等大卡片。
- 手機取消雙欄，頭條後直接接日期流。
- 優點：兼顧最近重點與瀏覽效率，編輯層級清楚。
- 代價：最新一則會自然獲得較高視覺權重。

### B｜日期索引

- 第一屏左側為年份／月份索引，右側直接從最新日期開始列出標題、摘要與類型。
- 圖片降為輔助縮圖；篩選與日期索引形成固定工作列，但不遮內容。
- 手機把日期索引改為原生下拉與可展開月份。
- 優點：資訊密度最高，長期累積後最好找。
- 代價：照片與敘事感較弱，初訪者可能覺得像資料庫。

### C｜主題編輯網格

- 第一屏以 2:1 不等寬網格展示三則內容，後續依主題分區而不是單純日期流。
- 篩選器在頁首下方橫排；分區內使用一大兩小，不做等寬三卡。
- 手機維持主題分區，但全部改單欄。
- 優點：不同內容類型可被看見，不會全被日期淹沒。
- 代價：同一則若跨主題，需要嚴格去重；維護規則較多。

## 03 田間知識與資源

第一屏任務：不要求使用者先懂網站分類，而是從「現在要處理什麼」開始找到可信內容。

### A｜任務清單（設計建議）

- 第一屏直接列六個動詞任務，每項顯示一句說明與目前可用內容數；未開放項採既定白底灰點狀態。
- 第二層才提供領域、族群與情境路徑。
- 桌機為左側任務序號、右側說明的展開式長列；手機維持同一閱讀順序。
- 優點：最符合農民的問題解決心智，不先學分類。
- 代價：跨多條件精細查找要到第二屏。

### B｜雙軸工作台

- 第一屏左側是「我要做什麼」，右側是「我遇到什麼情境／我是誰」；下方即時形成內容結果。
- 桌機為 4:8 工具＋結果雙欄；手機先顯示目前條件摘要，再展開篩選。
- 優點：同時呈現 v3 雙軸架構，內容量增長後仍可擴充。
- 代價：第一眼操作量較大，必須避免一次攤開所有條件。

### C｜情境起步

- 第一屏先用高溫、溫室、農機、農藥、搬運等真實工作情境作入口，再回到任務與領域。
- 圖片只在有核准素材時顯示，否則使用文字面，不以假圖補位。
- 手機採水平不可滑動的單欄情境清單，避免卡片跑馬。
- 優點：具體場景最容易理解，對第一次進站者友善。
- 代價：沒有內容的情境必須隱藏，入口數會隨內容狀態變化。

## 04 田野誌、田野紀錄、做農的人、農學堂

第一屏任務：讓讀者理解這裡是「人、地方、活動與觀察」的公共敘事，不是另一個知識資料庫。

### A｜田野雜誌（設計建議）

- 第一屏一則真實田野內容作主稿，旁邊列日期、地點、形式與兩則短訊。
- 後續交錯使用圖文橫列、短筆記與活動紀錄；版面有節奏但不改內容順序。
- 手機統一為日期／地點 → 標題 → 圖片 → 摘要。
- 優點：最能容納人物、照片與長短不一的田野內容。
- 代價：主稿需要明確的自動 fallback，不能讓失效精選留下空洞。

### B｜時間軸

- 第一屏直接顯示最近一次田野日期與地點；全部內容沿垂直日期軸排列。
- 地點與日期是導航，不另造色盤；同日內容可聚成一組。
- 手機日期軸移到左緣，內容仍是自然文件流。
- 優點：活動與田野過程的累積感最清楚。
- 代價：沒有真實田野日期的文章不能硬塞，需要回退到發布日期並清楚標示角色。

### C｜主題地圖

- 第一屏先展示五個固定田野問題，再把最新內容掛回各問題之下。
- 桌機用 5:7 主題索引＋內容預覽；手機先列主題，再列最近更新。
- 優點：能把分散活動累積成長期研究問題。
- 代價：初訪者想看「最近發生什麼」要多一次選擇。

## 05 五個田野主題頁

第一屏任務：清楚說明這一題在問什麼，並讓讀者看到不同形式的內容如何共同回答，而不是複製五篇相同卡片牆。

### A｜問題專刊（設計建議）

- 第一屏左側放正式問句與核心說明，右側呈現一則最能進入問題的真實內容。
- 後續分成「從田野看見」「從影音聽見」「從研究理解」三段；沒有內容的段落整段隱藏。
- 手機依問句 → 核心說明 → 主稿 → 其他證據排列。
- 優點：每題有清楚編輯觀點，又保留多內容形式。
- 代價：必須靠公開資格與去重規則維持段落可信。

### B｜導讀＋證據列

- 第一屏是窄版導讀，下面直接以時間、形式與來源列出全部相關內容。
- 桌機右側可有固定的「本頁收錄」索引；手機移到文章開頭的摘要列。
- 優點：研究者與回訪者掃描最快，資料關係清楚。
- 代價：情感與照片角色較弱。

### C｜交叉主題索引

- 第一屏顯示目前主題與其相鄰問題，內容以「同時回答哪些問題」的交叉線索排列。
- 不用關聯圖動畫，只用文字、細線與真實標籤。
- 手機把交叉關係改為每則內容下的文字連結。
- 優點：最能表現農業議題互相牽動，避免五道圍牆。
- 代價：理解成本最高，不適合內容量太少時啟用。

## 06 聽見田裡的聲音

第一屏任務：讓人快速選一集開始聽，並能依系列、主題與年份繼續找；不是把 39 張封面一次攤滿。

### A｜主打單集＋節目架

- 第一屏一集主打內容與清楚播放行動，右側列三集近期內容；系列與主題在下一層。
- 後續依系列形成不自動輪播的橫向節目架，桌機可分欄、手機改直列。
- 優點：第一步最明確，適合推廣近期內容。
- 代價：主打規則需要自動 fallback，且大量舊集的掃描效率普通。

### B｜播放清單（設計建議）

- 第一屏保留一個迷你目前播放區，主要內容立即進入可篩選的單欄 episode list。
- 每列固定呈現播放、集數／日期、標題、長度與主題；封面縮成一致輔助尺寸。
- 手機每列仍保留至少 44px 播放控制，metadata 換行而不截斷標題。
- 優點：39 集以上仍好找、好比較，最符合「先選一集」。
- 代價：視覺較像聲音檔案館，封面作品感較弱。

### C｜聲音年表

- 第一屏以年份與系列作索引，單集沿時間軸排列；近期集數在右側顯示較完整摘要。
- 手機先選年份，再讀單欄內容；不破壞瀏覽器返回。
- 優點：能看見計畫與地方聲音長期累積。
- 代價：找特定主題仍需要額外篩選；最新內容不一定最突出。

## 07 研究、出版、資源與倡議

第一屏任務：先說清楚研究如何轉成可用行動，再讓專業使用者快速核對成果、出版與外部資源。

### A｜研究到行動路徑（設計建議）

- 第一屏以「問題 → 研究 → 共作 → 公開成果」四步直向路徑呈現，旁邊放最新核准成果。
- 子頁沿用同一脈絡：出版、資源與倡議是不同證據出口，不是四個孤島。
- 手機把四步改為有序直列，不用橫向流程圖。
- 優點：一般讀者也能理解研究價值，符合網站名稱中的「共建」。
- 代價：專業讀者要多捲一屏才到完整書目。

### B｜出版書架

- 第一屏直接列研究出版與成果類型；左側為年份／成果類型，右側為完整引用與下載狀態。
- 研究主頁也採書架邏輯，倡議與相關資源放在獨立導讀區。
- 優點：學術查找最直接，APA 與來源狀態容易核對。
- 代價：計畫如何走到行動的故事較薄。

### C｜證據索引

- 第一屏以「研究問題、對象、方法、產出、可用資源」作欄位索引，內容採表格與卡片自適應。
- 桌機可掃描多欄；手機每筆改為欄名＋內容的直排卡，不允許表格撐破 viewport。
- 優點：治理與查核最清楚，適合成果日後增加。
- 代價：介面感最強，若目前成果量少會顯得空。

## 08 認識尊嚴農業與研究團隊

第一屏任務：回答「你們是誰、為什麼做、在哪裡做、由誰負責」，建立信任後才看組織細節。

### A｜計畫敘事（設計建議）

- 第一屏用計畫核心句、場域與合作機構形成左文右圖；下方依起點、方法、合作、目前行動展開。
- 團隊頁先說角色與責任，再列人物，不以頭像牆開場。
- 手機文字先於圖片；沒有照片的人使用既定中性佔位，不製造假肖像。
- 優點：信任建立最完整，也能容納場域照片。
- 代價：想直接找某位成員要多捲一段。

### B｜機構檔案

- 第一屏左側為計畫事實表，右側為簡短宗旨；合作、場域、團隊與聯繫形成清楚索引。
- 團隊採角色分組的名錄列，不做等大頭像卡牆。
- 優點：資訊查找最快，適合老師、合作單位與審查者。
- 代價：人的溫度與地方感較少。

### C｜人物與場域

- 第一屏以一張真實場域照片與一段核心引言進入，接著用人物／地方交錯的圖文列說明計畫。
- 團隊資訊嵌入實際工作場景，人物卡只承擔聯絡與角色。
- 優點：最能表現共作關係，不像制式研究計畫頁。
- 代價：需要足夠且授權清楚的照片；素材不足時必須降級為 A，不用假圖補。

## 09 文章單篇：消息、田野／活動、Podcast

第一屏任務：讓讀者先判斷這是什麼內容、值不值得讀／聽，再進入不受干擾的 780px 長文。三種內容共享閱讀骨架，只有第一屏媒體角色不同。

### A｜純閱讀（設計建議）

- 第一屏依序為麵包屑、內容類型、標題、摘要／metadata、主圖或播放器；正文置中 780px。
- 延伸閱讀、上下篇與來源放在正文後，不做永久側欄。
- 手機保持相同文件順序；H1 固定 48px 的既定規則另由 breakpoint 安全換行處理。
- 優點：最安靜、最不易過時，也最適合大字／特大字。
- 代價：長文中段沒有快速目錄。

### B｜欄外導覽

- 桌機正文右側增加窄欄，顯示本頁目錄、來源與相關內容；正文仍保持 780px，不被側欄壓窄。
- 側欄只在內容具真正 H2／H3 時出現；沒有章節就整欄隱藏。
- 手機將目錄移到正文前的可展開區，不能固定遮住內容。
- 優點：研究長文與教學內容最好導航。
- 代價：短消息或沒有正確標題結構的舊文會退化成 A。

### C｜雜誌開場

- 第一屏讓真實照片／播放器與標題形成 7:5 分割；metadata 成為欄外資訊，正文仍回到 780px。
- 消息用照片、田野文用日期地點、Podcast 用播放器作第一屏媒體，不硬套同一張圖。
- 手機先標題與 metadata，再媒體與正文，避免文字壓圖。
- 優點：不同內容型態辨識最強，照片與聲音有舞台。
- 代價：首屏高度較大，無媒體文章必須回退到 A。

## 明日選擇格式

可直接回覆：

```text
01 首頁：A
02 最新消息：C
03 田間知識：A
04 田野入口：B
05 五個田野主題：A
06 影音中心：B
07 研究與行動：A
08 關於與團隊：C
09 文章單篇：A（但 Podcast 第一屏用 C）
```

選擇室也會自動產生同一格式。所有選項預設未勾選，設計建議只提供判斷依據，不替 Bobo 做決定。
